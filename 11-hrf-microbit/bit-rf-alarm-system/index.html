🔐 How It Works
  1. The alarm system sends and receives commands over RF (radio frequency) on a fixed channel (433 MHz). Pressing "Arm" or "Disarm" on the remote transmits a code wirelessly.
  2. In Basic mode, the system uses a fixed code ("1234") sent as plaintext. Any device on the same frequency can listen and read the code — no encryption, no protection.
  3. A jammer floods the RF channel with noise, drowning out legitimate signals. While jamming is active, the alarm cannot receive arm/disarm commands — signal quality drops to near zero.
  4. A replay attack records the disarm code when it is transmitted, then retransmits the captured frame later. In Basic mode this works perfectly — but Secure mode uses rolling codes that expire after one use.
🧪 Lab
  1. Make sure the alarm is in Basic mode (toggle off). Arm the alarm, then press "Jam Signal" and try to disarm — notice the command fails while jamming is active.
  2. Stop jamming, then press "Record & Replay". Disarm the alarm normally — the replay tool captures the disarm frame. Now arm the alarm again and press "Record & Replay" to retransmit the captured code — the alarm disarms!
  3. Switch to Secure mode (rolling codes). Arm the alarm, then try the replay attack again — it fails! The code has already been used and is no longer valid.
  4. Observe the rolling code display below the signal meter. Each arm/disarm command generates a unique code. Compare Basic mode (always "1234") with Secure mode (changes every time).
🏆 Challenge

Challenge 1 — Disarm Without the Code

The alarm is armed in Basic mode. Use only the attack tools (jam and replay) to disarm it without knowing the code. Hint: record first, then replay.

Challenge 2 — Defeat Rolling Codes

Switch to Secure mode. Can you still disarm the alarm with a replay attack? Why does it fail? Discuss how rolling codes prevent replay attacks.

Challenge 3 — Design an Unbreakable Alarm

Imagine you are building a real alarm system. What features would you add beyond rolling codes? Think about encryption, frequency hopping, two-factor authentication, and tamper detection.

❓ Help
What is this app?

An RF alarm simulator that teaches you how wireless alarm systems work — and how attackers exploit them using jamming and replay attacks.

Do I need a real micro:bit?

No! This app simulates everything in your browser. But you can build a real version with two micro:bits using the radio blocks.

Is this legal to try on real alarms?

No. Jamming and spoofing real radio signals is illegal in most countries. This simulation is for educational purposes only.

What are rolling codes?

Rolling codes generate a new unique code for every transmission. Even if an attacker captures a code, it cannot be reused — the system has already moved to the next code.

📡 RF Jamming

RF jamming floods a radio channel with noise, preventing legitimate devices from communicating. Attackers use it to block alarm disarm signals, keeping alarms from responding to commands.

🔄 Replay Attacks

A replay attack records a valid wireless transmission and retransmits it later. If the system uses fixed codes, the replayed signal is accepted as genuine — the receiver cannot tell the difference.

🔑 Rolling Codes

Rolling codes (also called hopping codes) use a synchronized counter between transmitter and receiver. Each code is valid only once, making captured codes useless for replay attacks.

🔒 Secure RF Protocols

Modern secure RF protocols combine rolling codes with AES encryption, frequency hopping, and challenge-response authentication. This makes jamming, replay, and spoofing attacks extremely difficult.
