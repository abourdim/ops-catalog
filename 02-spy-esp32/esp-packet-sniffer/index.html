📚 How It Works
01 Enable Monitor Mode

The ESP32 WiFi chip switches to promiscuous mode, receiving ALL wireless frames in range regardless of destination address.

02 Capture Raw Frames

Every 802.11 frame (management, control, data) is intercepted. The callback function receives the raw bytes including headers.

03 Decode Headers

The frame control field reveals the type and subtype. Source/destination MAC addresses are extracted from fixed offsets in the header.

04 Identify Devices

MAC OUI prefixes identify manufacturers. RSSI values estimate distance. Probe requests reveal device names and saved networks.

❓ Help
What is this app?

A WiFi packet sniffer simulator. It shows how ESP32 monitor mode captures 802.11 frames and displays them on a radar.

Is this real WiFi sniffing?

No, this is a browser simulation. Real sniffing requires an ESP32 in promiscuous mode. This app generates fake traffic for learning.

What are 802.11 frames?

802.11 is the WiFi standard. Frames are packets sent wirelessly: beacons announce networks, probes search for networks, data carries payloads.

Is my data private?

Yes. Everything runs locally in your browser. No data is sent anywhere.

📡 Monitor Mode

Promiscuous/monitor mode lets the WiFi chip capture ALL frames, not just those addressed to it. The ESP32 supports this natively.

📦 802.11 Frames

Three main types: Management (beacons, probes, auth), Control (RTS/CTS, ACK), and Data (actual payload). Each has a 2-byte frame control field.

📶 RSSI

Received Signal Strength Indicator measures signal power in dBm. Closer to 0 = stronger. Typical: -30 (excellent) to -90 (weak).

🔒 Privacy

Local-first, privacy-first. All data stays in your browser. No tracking, no analytics, no external calls.
