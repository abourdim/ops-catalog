📚 How It Works
1
BLE Advertising Basics

BLE devices broadcast advertisement packets every 20ms-10s. These packets contain up to 31 bytes of data visible to any scanner in range. ESP32 can both advertise and scan simultaneously.

2
Beacon Protocols (iBeacon & Eddystone)

iBeacon uses UUID (16 bytes) + Major (2 bytes) + Minor (2 bytes). Eddystone-UID uses Namespace (10 bytes) + Instance (6 bytes). Both protocols have reserved fields we can hide data in.

3
Steganography in Beacons

We encode secret messages into UUID bytes, major/minor fields, or namespace data. A normal scanner sees a valid beacon; only our decoder extracts the hidden message from the right fields.

4
Proximity & RSSI

RSSI (Received Signal Strength Indicator) measures signal power in dBm. Closer beacons have stronger signals (-30 dBm = very close, -90 dBm = far away). We use this for proximity-based message reveal.

❓ Help
What is BLE advertising?

BLE (Bluetooth Low Energy) advertising is a one-way broadcast mechanism. Devices send small packets of data that any nearby scanner can receive, without pairing. ESP32 supports both advertising and scanning.

What are iBeacon and Eddystone?

iBeacon (Apple) and Eddystone (Google) are standardized beacon protocols. iBeacon uses UUID + Major + Minor fields. Eddystone supports UID, URL, and TLM frames. Both ride on BLE advertisement packets.

What is steganography in beacons?

Steganography hides messages in plain sight. In beacon context, we embed secret data within standard beacon fields (like UUID bytes) so normal scanners see a valid beacon but miss the hidden message.

How does RSSI relate to distance?

RSSI (Received Signal Strength Indicator) decreases with distance. Using the log-distance path loss model: d = 10^((TxPower - RSSI) / (10 * n)), where n is the path loss exponent (typically 2-4).

📡 BLE Advertising

BLE advertisement packets are 31 bytes max. They contain AD structures with type and data fields. The ESP32 BLE stack allows custom advertisement data for creative applications.

📍 Beacon Protocols

iBeacon: 0x4C000215 prefix + 16-byte UUID + 2-byte Major + 2-byte Minor + 1-byte TX. Eddystone-UID: 0xAAFE service UUID + 10-byte Namespace + 6-byte Instance ID.

🕵️ Steganography

Steganography is the art of hiding information in plain sight. In BLE beacons, we can encode ASCII characters into UUID bytes, spread bits across Major/Minor fields, or modulate TX power patterns.

🔒 Privacy

This app runs entirely in your browser with simulated BLE. No real Bluetooth signals are transmitted. All data stays local. No tracking, no analytics, no external calls.
